## Reading these numbers

- **Headline.** Every fine-tune scores above base. qv_r16, all7_r8 are nominally significant (p < 0.05). After Holm correction over the 5 comparisons with base, none is significant at 0.05.
- **One seed per config.** Seed-to-seed variance is not measured, so part of any gap between two fine-tunes may be training noise rather than the config.
- **Fine-tuning reshuffles which questions are right far more than it raises the total.** Every run gains 74–88 questions over base and loses 55–67. 675 questions are right in all six evals and 149 in none.
- **Base is strong and probably contaminated.** Untuned, it already writes Spider-gold quirks such as `Country ,  COUNT(*)` with the double space, so Qwen2.5-Coder likely saw Spider in pretraining. That caps the headroom fine-tuning can show.
- **The column-order check.** The harness compares columns positionally, which is stricter than the official test-suite eval. Allowing any column order raises every run by 2.3–3.2 points and helps base by 3.2, so the strict Δ is the larger estimate of the fine-tuning gain. Strict: all7_r8 77.56, qv_r16 77.47, attn_r8 76.79, qv_r8 75.92, qv_r4 75.92, base 74.95. Any column order: qv_r16 80.17, all7_r8 79.88, attn_r8 79.40, qv_r8 78.72, qv_r4 78.53, base 78.14.
- **What fine-tuning changes, from inspecting a sample of all7_r8's won and lost questions:**
  - It gains by adopting Spider conventions: INTERSECT for "both X and Y", `=` instead of `LIKE '%x%'`, literals copied as written, and fewer needless joins.
  - It loses by inventing Spider-style snake_case column names that aren't in the schema (`pet_type` for `PetType`, which surfaces as `no such column`), and occasionally by dropping a needed DISTINCT.
- Difficulty breakdown (easy/medium/hard/extra) is not computed yet; see CLAUDE.md, Eval-harness hardening.
